# CsgoBox

Minecraft **1.20.1 / Forge 47.2.20 / Java 17** 的开箱模组。

## 构建和测试

Windows：

```powershell
$env:JAVA_HOME = '你的 JDK 17 目录'
.\gradlew.bat test build
.\gradlew.bat runGameTestServer
```

Linux / macOS：

```sh
bash ./gradlew test build
bash ./gradlew runGameTestServer
```

模组文件在 `build/libs/csgobox-1.11.0.jar`。首次构建需要下载 Forge 和 Minecraft 依赖。
GameTest 在 `run-gametest/` 下使用独立的开发环境，请勿将该目录指向正式服务器。

箱体模型的 Blockbench 编辑工程位于 `blockbench/csgo_box.bbmodel`，内嵌原贴图，并附 `csgo_box.png` 和导回说明。使用 Java 方块/物品格式导出到 `src/main/resources/assets/csgobox/models/item/csgo_box.json`，贴图导出到 `textures/item/csgo_box.png`；物品沿用闭合模型；地面动画使用 `models/block/animated/` 下的箱体／箱盖分件。修改源模型后运行 `python tools/export_ground_models.py` 重新生成分件，具体说明见 `blockbench/README.md`。

## 配置与使用

服务端首次启动会生成 `config/csbox/box.json`。客户端不读取本地奖池配置。

客户端首次启动会生成 `config/csgobox-client.toml`，由 Forge 自动读取并监听修改：

```toml
[display]
blurEnabled = true
backgroundOpacity = 0.5
tacz3dPreview = true
```

这三个选项分别控制开箱模糊、背景不透明度（0–1）和 TaCZ 中奖枪械的三维检视。光影冲突时可关闭模糊；特殊枪包显示异常时可关闭三维检视，回退到背包图标。设置不改变奖池或服务端概率。

- 右键主手的箱子查看奖池，点击开箱后按奖励页的消耗方式扣除物品并发奖：仅箱子、仅钥匙、箱子和钥匙，每种物品每次消耗 1 个。仅钥匙会保留箱子；仅箱子不要求钥匙。所需物品可使用任意物品，带 NBT 时必须完整匹配，只有物品 ID 时按物品类型匹配。
- 背包开箱的奖励在播放动画前发放；关闭界面或正常断线不会取消发奖，也不能重新领取同一次奖励。地面开箱按下述动画结束后掉落。
- 优先合并背包里已有的同类堆叠，只有剩余放不下的部分才掉落。
- **地面开箱**：拿着有效奖池的箱子，Shift＋右键放到有完整支撑面的地面上；朝向随玩家改变，使用现有箱体模型。普通右键仍走原开箱界面。
- 手持匹配钥匙右键地面箱子开始开箱，主手／副手均可，只有背包里有钥匙不够。缺少或拿错钥匙时提示具体钥匙名称，保留自定义名称；仅箱子模式不要求钥匙。
- **地面动画**：服务端确认钥匙并固定中奖结果，播放约 0.8 秒开盖动画，再在箱内显示实时滑条；滑条减速结束并短暂停留后，从箱体上方弹出完整奖品，按普通掉落物拾取。完成前不发到背包或地上；附近玩家看到同一进度，后来进入区块也能接续观看。
- **空箱**：地面开箱完成后保留箱体并失去抽奖功能，右键自由切换开／关，不需要钥匙。破坏后掉落对应外观的独立空箱物品，可像普通方块直接右键放置；空箱不带奖池 ID，不会因重新放置、编辑奖池或改名而恢复奖励。
- 地面箱在三种消耗模式下都会变成一次性装饰空箱；`key`／`both` 在开始时扣除一把钥匙，`box` 不需要钥匙。背包开箱仍遵循原消耗方式，其中仅钥匙保留可抽奖箱子。
- 未开箱时敲掉箱子或拆除支撑，只掉回带原奖池 ID 的未开箱物品，不发奖。动画期间阻止普通挖掘和爆炸破坏；拆支撑时先保留动画，完成后掉落空箱。强制管理操作移除动画箱时结算待发奖品并只返回空箱，不退回可抽奖箱子。
- 放置和右键尊重 Forge 事件、交互距离及权限。动画结果和必要展示数据临时保存在服务端方块实体中，正常保存、卸载区块、离线后仍保留固定奖品，不重新抽奖；完成后清理。奖品生成被事件取消时继续保留待发状态并重试，不重复扣钥匙。未开箱仍只保存 `PoolId`，不嵌入整份奖池。
- 箱子 NBT 只保存固定奖池标识，例如 `{PoolId:"csgobox:weapons_supply"}`。开箱始终使用当前服务端配置，物品内不保存奖池或历史版本；奖池改名不会改变已发箱子的归属及堆叠，箱子显示名称跟随服务端目录更新。
- 创造物品栏通过服务端同步的 ID／名称目录显示配置箱子；切换服务器时清空该目录。保存或重载后重新打开创造物品栏即可看到更新。
- 箱子物品提示默认显示可展示奖励数量，按住 **Shift** 展开奖励列表。每项只显示按蓝、紫、粉、红品质着色的物品名，不显示数量、概率或金色奖励；自定义名称保留文字，颜色统一使用品质色。列表来自服务端的名称摘要，登录、编辑保存和 `/csgobox reload` 时同步，不写入箱子 NBT。高级提示模式才显示奖池 ID。
- 主开箱预览的常规奖品可点击进入检视页，拖拽旋转、松手回正，按住 Shift 查看原物品说明。检视不抽奖、不扣物品、不播放中奖音效。点击「返回」或 Esc 回到原预览。
- 主预览的传奇入口使用新的 MC 像素风透明图标，点击后显示当前奖池全部金色奖品的真实图标和名称，每页 32 项、最多 8 页，可用箭头或滚轮翻页。列表条目还可继续点击检视；返回依次回到传奇列表和主预览，并保留列表页码。
- 服务端在开箱预览数据中同步传奇物品以供检视，保留型号和 NBT；权重、掉落和获取规则仍不发送给普通玩家。箱子的 Shift 提示继续只列非金色物品名称。浏览中的预览每 10 秒续期一次，续期校验原玩家、令牌、手持箱子和槽位，不复活已过期、被替换或已经消费的预览。
- 玩家开箱界面保留原版 CSGO 风格与相对布局：上方大箱子、下方两排奖品、右下角开箱/关闭按钮、中央滚动条和黄色指针。二级检视页面共用同一画布和模糊背景，死亡或断线时退出整个页面层级。
- 预览、滚动动画和中奖页共用 480×270 的逻辑画布，随窗口等比例居中缩放；非 16:9 窗口保留边缘空间，改变 Minecraft GUI 缩放不会单独放大按钮或模型。按住模型可顺着鼠标方向旋转，拖出区域仍可继续；松手短暂停留后平滑回正，回正途中可以重新拖拽。
- 滚动带保留原有中心、卡片尺寸和圆形聚焦区域；第一帧即铺满卡片，立即从当前位置向左滚动，不设开场停留。圆形边缘柔化，外侧遮罩覆盖整个窗口，包括非 16:9 窗口的留边。两侧卡片轻微收缩、倾斜并整体渐隐，中央指针始终清晰。预览／滚动图标按普通物品、刀剑工具及 TaCZ 长枪／手枪适配。滚动中的图标仍使用物品的 GUI 渲染，只有中奖物品进入三维检视。
- 动画连续减速到服务端确定的奖品，停留约 0.45 秒后，用约 0.7 秒过渡到原有检视位置。整个过程不再次抽奖；取消页面不撤回已发奖品。页面间复用已有模糊效果，避免重新加载造成闪动。
- 渐隐使用一个随窗口尺寸复用的离屏缓冲，只渲染可见卡片；物品显示类别在打开页面时解析，关闭页面释放缓冲，不增加运动模糊或多次枪械拖影渲染。
- 奖品悬浮信息复用当前物品的说明，切换物品、Shift/Ctrl/Alt 或高级提示模式立即更新，动态说明最多缓存 250 毫秒。保留原版提示定位及 Forge 提示图片、字体和渲染事件；拖模型时不会误弹奖品提示。

管理员命令（权限等级 2）：

```text
/csgobox reload
/csgobox give csgobox:weapons_supply
```

`give` 按奖池 ID 给执行命令的玩家一个指定箱子，支持 ID 补全。编辑器物品也需要权限等级 2。

### 游戏内奖池编辑器

创造物品栏中获取「奖池编辑器」后，拿在主手右键打开。开发环境可运行 `./gradlew runClient` 查看界面。

- **奖池列表**：按名称或 ID 搜索并加载配置、新建、复制、删除。编辑器自动为新建／复制的奖池生成固定 ID，顶部及列表悬浮提示显示该 ID；更改名称直接更新当前奖池，已有箱子仍可使用。同名奖池按不同 ID 区分。删除前确认已保存的奖池名称和 ID；删除后对应获取规则、目录和开箱预览更新，已有该 ID 的箱子无法继续开箱。删除同样校验管理员权限、当前编辑器和配置版本，版本冲突时拒绝删除。
- **奖励页**：蓝、紫、粉、红、金五档独立分页，每页 27 项，整个奖池最多 256 项。常规奖励按添加顺序展示，主开箱列表每页 20 格，所有金色奖励合并为一个传奇入口并占一格。总展示格数超过 20 才显示上下翻页按钮，鼠标在列表上也可滚轮翻页；从检视页返回保留页码。传奇入口仍可打开完整金色清单，箱子 Shift 提示仍列出全部非金色名称。
- 蓝、紫、粉、红品质分别标出前 **7／5／3／2** 个建议格，空建议格显示「+」。这是搭配建议，超出后仍可添加；金色不标建议格，也不占常规名额。
- 背包取样只通过拖入：拖到奖励区添加奖励，拖到右侧所需物品槽设置钥匙，右键槽位或点击 × 清空。左键单击背包样品不会添加，拖到目标外也不会添加。取样只复制配置，不移动真实物品；奖励保留数量、名称、附魔和 NBT，所需物品统一为 1 个。
- **消耗方式**位于奖励页，可循环选择「仅箱子／仅钥匙／箱子和钥匙」。仅箱子可保留钥匙字段供后续切换，但开箱不要求或扣除钥匙；另两种模式必须配置所需物品。清空所需物品会切回仅箱子并关闭钥匙获取规则。
- **物品获取页**：先选择箱子或钥匙，再从左侧获取方式列表切换合成、掉落、村民交易，右侧编辑所选规则。各方式分别启用，可同时开启三种方式；勾号表示已启用。合成为 3×3 有序配方，每格消耗一个材料，可设置产出数量。从背包拖入目标材料槽，右键清空。无 NBT 材料按类型匹配，带 NBT 材料严格匹配。空边缘会裁掉，允许原版镜像和移动配方。
- 掉落分别配置实体 ID、百分比概率和数量；多种实体用逗号分隔，JSON 概率为 0–1。村民交易设置职业 ID、等级 1–5、第一／可选第二材料及数量、产出、最大使用次数、村民经验。交易加入原版的随机候选列表，不保证每位村民都会出现；已有村民已经生成的交易保留，后续新生成的交易使用新规则。
- **概览预览页**：集中设置五档权重、幸运值开关，展示各档及每条奖励的实际概率；可输入幸运值或使用玩家当前幸运值，不改变玩家属性。概率按全部奖励计算，重复条目概率累加，隐藏条目也计入。关闭「幸运值影响」后服务端抽奖和预览都忽略玩家幸运值；旧配置默认开启。
- **保存**：`Ctrl+S` 或「保存并应用」，服务端重新校验后立即生效，并保留当前界面。无效输入会阻止保存；切换奖池、新建或关闭前会提示未保存的修改。
- **获取测试箱子**：已保存且没有未保存修改时，领取一个箱子；消耗方式要求钥匙时才附送一把匹配钥匙。由服务端校验管理员权限、当前编辑器和奖池版本；重复请求不会重复发放。背包满时掉落在脚边；此箱子正常开箱和发奖。
- **冲突保护**：按 ID 和所加载配置的版本校验保存。新建／复制不会覆盖已有 ID；其他管理员或文件编辑已修改同一奖池时拒绝覆盖，可重新从列表加载最新文件版本。
- 完整配置只发送给具有权限等级 2 且打开编辑器的管理员；普通玩家仍只收到开箱展示数据。客户端窗口缩小或调整 GUI 缩放时，编辑器整体自适应。

## JSON 格式

每个奖池必须有唯一、稳定的 `id`，`name` 是可修改的显示名称。例如：

```json
[
  {
    "id": "csgobox:example",
    "name": "示例箱",
    "key": "csgobox:csgo_key0",
    "consumption": "both",
    "drop": 0.12,
    "luckEnabled": true,
    "random": [2, 5, 6, 20, 625],
    "entity": ["minecraft:zombie"],
    "grade1": ["minecraft:diamond.withCount(3)"],
    "grade2": [],
    "grade3": [],
    "grade4": [],
    "grade5": ["minecraft:netherite_sword.withTags{Damage:0,Enchantments:[{id:\"minecraft:sharpness\",lvl:4s}]}"]
  }
]
```

- `random` 是相对权重，顺序仍为 **金、红、粉、紫、蓝**，不是百分比。空品质池不参与抽奖，其余有效权重重新归一化；权重为 0 的品质永远不会抽中。
- 同品质内部均匀抽取。`luckEnabled` 为 true（或省略）时，幸运值对有正权重、非空的前四个品质增加 `2 × luck`（取整）权重，再统一计算总权重。负幸运值导致所有有效权重为零时回退到基础权重；false 时始终使用基础权重。
- `key` 可以为空字符串；非空时支持物品 ID 或带 NBT 的物品描述，数量必须为 1。
- `consumption` 可为 `box`（仅箱子）、`key`（仅钥匙）、`both`（箱子和钥匙）。`key`／`both` 要求非空的 `key`；未知值拒绝保存或加载。旧配置省略时，有钥匙默认 `both`，空钥匙默认 `box`，保留原有行为。
- `displayOrder` 记录常规奖励添加顺序，例如 `[4,1,4]` 依次指向第一条红色、第一条蓝色、第二条红色；每档出现次数必须与该档条目数一致，不包含金色。省略时按蓝、紫、粉、红的原有顺序初始化。
- `acquisition` / `keyAcquisition` 分别保存箱子／钥匙的获取规则，各含 `crafting`、`drop`、`trade`。省略的新规则默认关闭；旧 `drop` / `entity` 会导入箱子掉落规则。存在 `acquisition` 时以它为准，旧字段仅保留为镜像。建议通过编辑器生成完整配置。
- `id` 不超过 128 字符，格式为 `命名空间:路径`，使用小写英文、数字和资源标识允许的符号；例如 `csgobox:weapons_supply`。ID 不应随名称变更；名称可重复，长度为 1–128 字符。
- `.withTags{...}` 使用原生 SNBT，无需 CraftTweaker。`.withCount(n)` 可在标签前或后，数量为 1 到该物品的最大堆叠数。
- 缺失／重复／无效 ID、缺失物品、无效 NBT、负权重及空奖池会报错。最多配置 512 个箱子，每个箱子最多 256 条奖励，奖励文本合计最多 65536 字符；文件上限 2 MiB。
- 重载先完整读取和校验，失败时继续使用旧配置；保存使用临时文件替换，且不会覆盖一个已经损坏的 JSON 文件。
- 热加载由 `/csgobox reload` 手动触发；没有文件轮询器。保存／重载同步配方和奖励目录，重新计算在线玩家的合成结果，更新掉落和后续村民交易候选。原版 `/reload` 后也会重新挂载配置配方。已打开的开箱预览会失效，重新右键箱子即可。
- 配方 ID 使用 `csgobox:configured/box/<奖池命名空间>/<路径>` 与 `csgobox:configured/key/...`，请勿在数据包中占用这两个保留目录。动态配方用原版工作台与配方书，无需额外模组；不接管已有村民交易数据。

获取规则示例（放入 `acquisition` 或 `keyAcquisition`，各开关互相独立）：

```json
{
  "crafting": {
    "enabled": true,
    "ingredients": ["", "minecraft:iron_ingot", "", "minecraft:iron_ingot", "minecraft:chest", "minecraft:iron_ingot", "", "minecraft:iron_ingot", ""],
    "count": 1
  },
  "drop": {"enabled": true, "chance": 0.1, "entities": ["minecraft:zombie"], "count": 1},
  "trade": {
    "enabled": true, "profession": "minecraft:weaponsmith", "level": 2,
    "cost": "minecraft:emerald.withCount(8)", "secondCost": "", "count": 1, "maxUses": 12, "xp": 5
  }
}
```

## 升级说明

当前版本 **1.11.0、网络协议 13**，客户端和服务端均需更新。地面箱改为开盖、箱内滑条、延迟掉落奖品并留下空箱；新增六种外观的独立装饰空箱，普通右键即可放置和开合。地面仅钥匙模式也会在一次开箱后变为空箱，背包模式行为保留。1.10.0 的分页、获取方式列表和 JEI 兼容，以及先前外观、检视与图标修复继续保留。原奖池 JSON 和未开箱物品无需迁移。

不提供旧示例箱的名称回退或 NBT 迁移；旧箱子需从创造目录、编辑器或命令重新获取。已有配置文件需为每个奖池填写唯一 `id`，缺失时会明确报错，不会清空或静默重建配置。当前工作区的配置已补充 ID 并保留全部奖励，修改前备份位于工作目录。奖励物品的 TaCZ 数据、附魔及其他 NBT 不变。

## 箱体外观

编辑器新增“箱体外观”标签页，可并排预览并选择六种模型，保存和复制奖池均保留选择。奖池 JSON 的 `appearance` 支持 `classic`、`gold`、`orange`、`green`、`rose_blue`、`yellow_metal`；缺省为保留的旧款做旧金箱 `classic`，未知值会拒绝加载并保留当前有效配置。

背包、手持、掉落物和开箱预览按服务器同步的奖池外观显示，箱子 NBT 仍只需要 `PoolId`。地面箱子将外观保存在方块状态，跟随原朝向渲染；编辑或重载后，已加载箱子在一秒内同步外观和碰撞范围。绿色扁平箱使用较矮的碰撞范围。主开箱界面布局保持不变。

六个使用原版奖励的示例见 [examples/box-appearances.json](examples/box-appearances.json)，具体 ID、获取命令及合并方式见 [示例说明](examples/README.md)。新建配置包含这些示例；升级已有配置不会覆盖原奖池。模型包的 Java 闭合模型已接入；可编辑 Blockbench 工程、原贴图、开盖快照与动画源保存在 `blockbench/appearances/`，运行时不需要 GeckoLib。

## TaCZ

兼容测试使用 [TaCZ 1.1.8-hotfix2 / Forge 1.20.1](https://www.curseforge.com/minecraft/mc-mods/timeless-and-classics-zero/files/9037989)。TaCZ 不是必装依赖，也不会打包进本模组。

- 在编辑器中从背包拖入完整枪械取样，保留 `GunId`、`GunDisplayId`、配件、弹药、开火模式和自定义名称。只填 `tacz:modern_kinetic_gun` 没有枪型，会提示从背包取样。
- 奖品列表沿用 TaCZ 图标；中奖页通过 TaCZ 的 FIXED 渲染上下文显示三维模型，支持原有拖拽回正。编辑器与开箱页保留 Forge 的物品提示图片和渲染钩子。开箱期间隐藏 TaCZ HUD，关闭页面后恢复。
- 客户端与服务端须装有对应的 TaCZ／枪包；本模组不会分发枪包或保证任意第三方模型都适合默认检视尺寸。
- 开发兼容测试：`./gradlew -PtaczCompat=true runGameTestServer` 或 `runClient`。此选项只为开发运行添加固定版本的 TaCZ。

## JEI

JEI 是可选客户端依赖，不需要安装在服务端，也不会打包进 CsgoBox。支持 Forge 1.20.1 的 JEI 15.20.0.106 及以上 15.x 版本；开发测试固定使用 15.20.0.106。开发运行：`./gradlew -PjeiCompat=true runClient`，可同时加 `-PtaczCompat=true`。

- JEI 物品列表显示服务器配置的全部箱子，按 `PoolId` 区分，同名或相同外观的箱子也不会合并。显示名称和模型跟随服务端目录。
- 查看箱子或钥匙的配方时，新增「箱子与钥匙获取方式」分类：合成显示完整九格材料和产出数量；掉落按实体列出名称、ID、概率和数量；交易显示职业、等级、两项材料、产出数量、次数及经验，并说明它是随机交易候选。
- 没有启用获取方式的配置箱子仍在物品列表中，获取页面明确标为未配置。钥匙获取规则独立展示；样品材料和产出保留 NBT。现有动态工作台配方也继续同步给原版及 JEI。
- 登录、保存、删除和重载配置后更新目录与获取页面；退出服务器时清空。数据来自当前服务器，不读取客户端本地奖池。获取方式同步包只包含已启用的公开获取规则，不包含抽奖权重、奖励清单或未启用方式的编辑草稿。
